# Контрольные вопросы — ЛР №2

## 1. Что такое процесс?

**Процесс** — это выполняемая программа, которая имеет собственное адресное пространство и системные ресурсы.

## 2. Что такое поток?

**Поток (Thread)** — это последовательность выполнения внутри процесса. Один процесс может содержать несколько потоков, которые выполняются независимо или совместно работают с одними и теми же данными.

## 3. Чем поток отличается от процесса?

**Процесс** — это отдельная выполняемая программа со своим адресным пространством и системными ресурсами.

**Поток** — это последовательность выполнения внутри процесса. Несколько потоков одного процесса могут совместно использовать его данные и ресурсы.

## 4. Что такое Task в C#?

**Task** — это объект, представляющий выполняемую или планируемую асинхронную операцию. Task позволяет организовать конкурентное выполнение операций и удобно работать с асинхронными методами через `async/await`.

## 5. Для чего используется Task.Run()?

`Task.Run()` используется для запуска операции в отдельной задаче, обычно с использованием потока из Thread Pool. Это позволяет не выполнять длительную синхронную работу непосредственно в текущем потоке.

В нашей лабораторной `Task` используется для обработки клиента отдельно от основного цикла приёма подключений.

## 6. Чем последовательное выполнение отличается от параллельного?

**Последовательное выполнение** — операции выполняются одна после другой. Пока первая операция не завершится, следующая не начнётся.

**Параллельное/конкурентное выполнение** — несколько операций могут выполняться с перекрытием во времени.

Например, если обработка каждого запроса занимает 10 секунд:

- последовательно: примерно 20 секунд для двух запросов;
- при перекрывающейся обработке: время будет близко к 10 секундам.

## 7. Почему простого запуска двух клиентов недостаточно, чтобы доказать параллельную обработку?

Потому что запросы могут быть очень быстрыми. Даже если запустить два клиента подряд, нельзя по самому факту запуска определить, обрабатывались ли они одновременно.

Поэтому в лабораторной используется искусственная задержка, позволяющая увидеть перекрытие обработки по временным меткам.

## 8. Какие данные в логах позволяют доказать, что два запроса выполнялись одновременно?

Нужно смотреть:

- время начала обработки каждого клиента;
- время завершения каждого клиента;
- идентификатор клиента;
- название операции;
- идентификатор `Task` или `Thread`.

Например:

```text
[10:15:01.120] Client 1 → START
[10:15:02.200] Client 2 → START
[10:15:11.125] Client 1 → END
[10:15:12.205] Client 2 → END
```

Здесь видно, что Client 2 начал обработку до завершения Client 1.

## 9. Зачем в эксперименте используется искусственная задержка?

Искусственная задержка нужна для того, чтобы обработка запроса занимала достаточно времени и можно было экспериментально увидеть параллельное выполнение.

В методичке для этого используется задержка **10 секунд**.

## 10. Что такое общий ресурс?

**Общий ресурс** — это данные или объект, к которому одновременно могут обращаться несколько клиентов или потоков.

В нашем варианте лабораторной общий ресурс — **свободное место на тренировке**.

Например:

```text
Capacity = 1
AvailablePlaces = 1
```

## 11. Что такое Race Condition?

**Race Condition** — это ситуация, при которой результат работы программы зависит от порядка и момента выполнения нескольких параллельных операций над общими данными.

## 12. Почему два клиента могли получить SUCCESS, если ресурс был только один?

Потому что оба клиента могли почти одновременно прочитать одно и то же значение:

```text
AvailablePlaces = 1
```

Первый клиент ещё не успел изменить ресурс, а второй уже прочитал старое значение.

В результате оба клиента решили, что место свободно, и оба выполнили бронирование.

Получается, например:

```text
Capacity = 1
Bookings = 2
AvailablePlaces = 0
```

Это является проявлением Race Condition.

## 13. Почему проблему Race Condition нельзя игнорировать в настоящей распределенной системе?

Потому что она может привести к некорректному состоянию общих данных и нарушению бизнес-логики.

Например, если имеется одно свободное место, система не должна позволять двум клиентам одновременно занять его. Без синхронизации могут появиться:

- двойное бронирование;
- некорректное количество ресурсов;
- потеря или перезапись данных;
- несогласованное состояние системы.

## 14. Какие механизмы синхронизации могут использоваться для решения проблемы Race Condition?

Для устранения Race Condition могут использоваться механизмы синхронизации, например:

- `lock`;
- `Mutex`;
- `Semaphore` / `SemaphoreSlim`;
- `Monitor`;
- атомарные операции `Interlocked`;
- транзакции и блокировки на уровне базы данных.

В нашей ЛР №2 Race Condition **специально не исправляется**, потому что по заданию её необходимо сначала воспроизвести и проанализировать. Исправление проблемы выполняется с помощью механизмов синхронизации в следующей лабораторной работе.
