# ЛР №4 — готовый запуск в Docker Compose (Arch Linux)

Проект продолжает ЛР №3: C# TCP-клиент → C# TCP-сервер → PostgreSQL.
Клиент отправляет JSON по TCP и не подключается к БД. Сервер и PostgreSQL запускаются через Docker Compose.

## 1. Установить Docker на Arch Linux

```bash
sudo pacman -Syu
sudo pacman -S docker docker-compose
sudo systemctl enable --now docker.service
sudo docker compose version
```

Если `docker` доступен только через `sudo`, на первом запуске все команды Docker ниже выполняйте с `sudo`. Добавление в группу `docker` даёт практически root-доступ; для лабораторной проще использовать `sudo`.

## 2. Запустить БД и сервер

Из корня распакованного проекта (там, где находится `compose.yaml`):

```bash
sudo docker compose up -d --build
sudo docker compose ps
sudo docker compose logs -f server
```

Дождитесь сообщения `Сервер фитнес-центра запущен на порту 5000`. Выйти из просмотра логов — `Ctrl+C`; контейнер продолжит работать.

При первом запуске Docker скачает образы PostgreSQL и .NET, соберёт сервер, создаст таблицы и добавит двух тренеров: Иванов Иван и Петрова Анна.

## 3. Запустить клиенты на хосте (Arch Linux)

Сервер и PostgreSQL работают в Docker, а клиенты запускаются обычными процессами на Arch Linux. Порт сервера `5000` опубликован на `127.0.0.1:5000`; PostgreSQL наружу не публикуется.

Установите .NET SDK, если он ещё не установлен:

```bash
sudo pacman -S dotnet-sdk
dotnet --info
```

Откройте второй терминал в корне проекта и запустите первый клиент:

```bash
dotnet run --project Client/Client.csproj
```

Чтобы проверить конкурентный доступ, откройте ещё один терминал в том же каталоге и запустите ту же команду второй раз. Клиенты по умолчанию подключаются к `127.0.0.1:5000`. При необходимости адрес и порт можно задать через `SERVER_HOST` и `SERVER_PORT`.

## 4. Как проверить функциональность

1. В меню клиента выберите `1` и зарегистрируйте клиента, например: Иван / Иван / Иванович / `+37060000001`.
2. Выберите `2`, укажите его телефон и абонемент. На сервере будут видны `операция 1`, `операция 2`, `COMMIT`.
3. Выберите `7` — ошибка без транзакции. Абонемент успевает записаться в `memberships`, но клиент не получает ссылку на него; операция демонстрирует частичное изменение.
4. Выберите `8` — та же искусственная ошибка с транзакцией. Сервер выполняет `ROLLBACK`; вставка отменяется.
5. Для проверки мест на тренировке запустите два клиента. В обоих выберите `3`, укажите разные зарегистрированные телефоны, одного тренера (например, Иванов Иван) и абсолютно одинаковое время. Ожидается один `УСПЕШНО` и один отказ, так как вместимость демонстрационного слота — одно место.
6. Для проверки результата бронирования/отмены используйте меню `5` и `4`.

## 5. Запустить автоматические проверки

Выполните команду из корня проекта (тесты запускаются отдельным временным контейнером, клиенты для обычной работы остаются на хосте):

```bash
sudo docker compose --profile test run --build --rm integration-test
```

Тестовый контейнер зарегистрирует отдельные тестовые записи и проверит:
- сохранение регистрации клиента;
- частичное изменение при ошибке без транзакции;
- отмену вставки после `ROLLBACK`;
- сохранение двух связанных изменений после `COMMIT`;
- конкурентное бронирование двумя клиентами (один успех, один отказ);
- возврат места после отмены тренировки.

При успехе последняя строка вывода — `ALL TESTS PASSED`. Тесты добавляют тестовые записи в БД, поэтому после запуска их можно увидеть в SQL-запросах ниже.

## 6. Проверить таблицы PostgreSQL

Команды выполняются на хосте, данные читаются через `psql` внутри контейнера БД:

```bash
sudo docker compose exec db psql -U fitness_user -d fitness_db -c '\dt'
sudo docker compose exec db psql -U fitness_user -d fitness_db -c 'SELECT id, last_name, first_name, phone, current_membership_id FROM clients ORDER BY id;'
sudo docker compose exec db psql -U fitness_user -d fitness_db -c 'SELECT id, client_id, name, price, duration_days FROM memberships ORDER BY id;'
sudo docker compose exec db psql -U fitness_user -d fitness_db -c "SELECT t.id, c.phone, tr.last_name, tr.first_name, s.training_time, s.available_places, t.status FROM trainings t JOIN clients c ON c.id=t.client_id JOIN training_slots s ON s.id=t.slot_id JOIN trainers tr ON tr.id=s.trainer_id ORDER BY t.id;"
```

Для просмотра результата двух демонстраций сравните `memberships` и `clients.current_membership_id`. При пункте 7 новая строка `memberships` остаётся, но не становится текущим абонементом; при пункте 8 количество строк не увеличивается, поскольку сработал `ROLLBACK`.

## 7. Остановка и очистка

```bash
sudo docker compose down
```

Данные остаются в томе `fitness_lab4_pgdata`. Полное удаление базы и данных (необратимо):

```bash
sudo docker compose down -v
```

SQL в `db/init.sql` автоматически исполняется только при первом создании пустого тома. Если вы меняли схему после первого запуска, либо удалите том командой выше (данные будут потеряны), либо примените SQL вручную.

## Реализовано для ЛР №4

- постоянное хранение клиентов, абонементов, тренировочных слотов и записей в PostgreSQL;
- регистрация клиента, покупка/назначение абонемента, бронирование, отмена и проверка доступности;
- TCP-сервер принимает нескольких клиентов; JSON-протокол из ЛР №3 сохранён;
- `lock` защищает критическую секцию резервирования; строка слота дополнительно блокируется через `SELECT ... FOR UPDATE`;
- `BuyMembership` и бронирование используют транзакции;
- пункты 7 и 8 клиента показывают частичное изменение без транзакции и `ROLLBACK` при ошибке;
- журнал сервера выводит время, клиента, операции, вход/выход из `lock`, результат и `COMMIT`/`ROLLBACK`.
